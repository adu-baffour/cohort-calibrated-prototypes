# Cohort-calibrated prototypes for few-shot open-set recognition

[![DOI 10.5281/zenodo.23695548](https://zenodo.org/badge/DOI/10.5281/zenodo.23695548.svg)](https://doi.org/10.5281/zenodo.23695548)

Code, fixed episode manifests and recorded results of the paper

> I. Adjei-Mensah and A. A. Baffour, *Cohort-calibrated prototypes for few-shot open-set recognition*, Neurocomputing (submitted, 2026).

Every table, figure and number of the paper regenerates from the recorded results with one command (`python scripts/reproduce.py all
--tier 1`), and every name in this repository is the paper's name (docs/naming.md maps them to the names of the registration documents).

## The method

Few-shot open-set recognition (FSOR) classifies queries from a small support set and rejects queries from unseen classes. CCP-A normalizes
each query-prototype similarity against a fixed bank of base-class images, the cohort:

1. Embeddings average an image and its mirror image, z(x) = n(g(x) + g(x̃)), and prototypes average the support features (Eqs. 1-2).
2. The cohort statistic m_K(v) is the mean cosine of v to its K = 1000 nearest bank images (Eq. 3).
3. CCP-A replaces the cosine c_k(q) with s_k(q) = c_k(q) − ½ [m_K(q) + m_K(p_k)] (Eq. 4); the label is argmax_k s_k(q) and the unknown
   score u(q) = −max_k s_k(q) (Eq. 5). CCP-QW weights the two corrections (Eq. 6).
4. A trained host keeps its labels and fuses its own unknown score D with a weight fixed on validation: H_fix = D + w u (Eq. 7).
5. The stratified cohort gap (SCG, Eq. 8) measures, on validation, how much more cohort affinity unknown queries have than known queries at
   matched raw similarity.

The code follows the paper: `ccp/embedding.py` (Eqs. 1-2), `ccp/cohort.py` (Eqs. 3-6), `ccp/fusion.py` (Eq. 7), `ccp/scg.py` (Eq. 8);
docs/protocol.md describes the protocol and every implementation detail.

## Results

Eight sequential, registered single-pass test rounds evaluate 10 hosts on four datasets (Table 1; docs/registration_log.md). CCP-A raises
the AUROC of every ResNet-12 host tested on mini-ImageNet by 0.58-4.44 points, by 1.84-5.50 points under transfer to CUB and by 0.86-8.03
points in all eight CLIP configurations; it lowers AUROC in 16 of 24 DINOv2 configurations, where global centering is often competitive.
Validation SCG has a Spearman correlation of 0.78 with the foundation-model test gains.

## Environment

All recorded results were computed on one workstation: Windows 11, Python 3.10.11, PyTorch 2.14 with CUDA 13.0, one NVIDIA GeForce RTX
4090 (24 GB), an Intel Core i9 processor and 128 GB of RAM. The versions of every package are pinned in `requirements.txt`. Tier 1
(below) runs on a CPU.

```bash
git clone https://github.com/adu-baffour/cohort-calibrated-prototypes && cd cohort-calibrated-prototypes
python -m venv .venv && source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt && pip install -e . --no-deps
pytest -q                                                    # CPU, synthetic data; about 15 s
```

For a GPU, install the CUDA build of the pinned torch and torchvision versions (pytorch.org).

## Data, checkpoints and release assets

- **Datasets.** mini-ImageNet, tieredImageNet, CIFAR-FS (CIFAR-100) and CUB-200-2011 are public benchmarks; their images are not
  redistributed. `scripts/prepare_data/` writes the arrays the code reads and checks their sha256 (docs/data.md). Set `CCP_DATA`.
- **Our checkpoints and recorded caches**: the FRN and DNPG checkpoints, one archive per host, and one archive with the per-episode test
  metrics and validation score caches that tier 1 reads. Download them from the GitHub release v2.0.0 (https://github.com/adu-baffour/cohort-calibrated-prototypes/releases/tag/v2.0.0) or from the Zenodo record
  (DOI [10.5281/zenodo.23695548](https://doi.org/10.5281/zenodo.23695548)); both hold the same files, listed with their sha256 in `MANIFEST.txt` and `SHA256SUMS`. Unpack them into one
  folder and set `CCP_ASSETS` to it (docs/checkpoints.md).
- **RFS (CIFAR-FS).** The RFS checkpoint is not redistributed, because the RFS code used to train it has no licence;
  `scripts/train/train_rfs_cifarfs.py --seed 0` reproduces it up to GPU non-determinism, and the evaluated checkpoint is available from the
  authors on request.
- **Third-party weights.** FEAT and TANE checkpoints, CLIP and DINOv2 weights come from their authors (links and sha256 in
  docs/checkpoints.md). Set `CCP_CKPT` to their folder followed by `$CCP_ASSETS/checkpoints`.
- **Third-party code** is cloned at pinned commits by `python third_party/clone.py <name>` (THIRD_PARTY_LICENSES.md).

Every checkpoint, bank, array and recorded file is checked against its sha256 before use.

## Figures with dataset images

Figures 1 and 4 of the paper show mini-ImageNet images and are not redistributed. `python scripts/make_figures.py Fig4` draws Figure 4
from the prepared mini-ImageNet arrays (`$CCP_DATA`); Figure 1 is the authors' draw.io drawing, whose PDF and source are pinned by sha256
(configs/paper_pins.json, results/PROVENANCE.md) and copied into place when present locally. Tier 1 checks Figure 4's selection and
plotted data without drawing the images. `scripts/release_scan.py` fails on any tracked file that contains dataset images.

## Reproduce

[REPRODUCE.md](REPRODUCE.md) lists every step with its inputs and runtime.

1. **From the recorded results** (CPU, about 2 minutes): `python scripts/reproduce.py all --tier 1` regenerates and checks Tables 1-8,
   the figures, every number of the text, the derived files and the detailed tables, and ends with "tier 1: all OK".
2. **From the released checkpoints** (GPU): `python scripts/reproduce.py val-equivalence --tier 2` re-evaluates every host on validation
   episodes and compares with the recorded outputs.
3. **From scratch** (GPU-days): `python scripts/reproduce.py training --tier 3` prints the training commands.

The test episodes were scored once per round, by the registered code; those single passes are the paper's numbers. Re-scoring test
episodes with this code is possible (REPRODUCE.md, tier 2, `--allow-test`) but is a new evaluation, not run by the authors for this release.

## Quickstart: DNPG with CCP on mini-ImageNet validation

```bash
export CCP_DATA=~/ccp-data CCP_ASSETS=~/ccp-assets CCP_CKPT=~/ccp-ckpt:$CCP_ASSETS/checkpoints
python third_party/clone.py DNPG
python scripts/build_bank.py --host dnpg_mini_seed0 --shot 1        # byte-identical to the pinned sha256
python scripts/evaluate.py --host dnpg_mini_seed0 --episodes valA_fsor_5way_1shot valB_fsor_5way_1shot --save-scores
# valB AUROC: host score 76.29, H_fix 77.31, K_fix 76.64, CCP-A 76.54 (equal to the recorded dry run of round (iii),
# results/recorded/validation/fsor_final_dryrun_val_mini-dnpg.json)
```
